# 循环细则(LOOP.md)

> `AGENTS.md` = 边界与状态机(短);`knowledge/` = 固件研究的判据与经验;`tools/templates/` = 交付物形态。

### 失败分诊(判据)
- **层: 假设 | 环境 | 信号** —— 工具不存在/路径错/依赖缺失/版本不匹配 ⇒ **环境**;输出格式或验证方式不可判定 ⇒ **信号**;
  环境验证通过但假设未命中 ⇒ **假设**。输出三行: `层: …` / `依据: <失败输出关键证据>` / `修正指令: <一条可直接执行的下一圈动作>`。
- **重跑规则**: 分诊为**环境/信号** ⇒ 修正后**重跑同一格**(那是暂时失败,换格是浪费);
  分诊为**假设**(格跑通了、结果就是否证)或该格确已用尽 ⇒ **换格/换面**(并写"用过哪些格、还剩哪些")。
- 附带溯源审计: 假设清单里凡涉及可识别组件(服务器/SDK/协议名)却标 `[RE]` 且无检索痕迹者,必须点出。

### 清理与生命周期(守则 7 的细则;**唯一所在**,别处只指针)

**只有两档**(由用户一句话切换:"这个目标收尾了" / "不要了" —— **放弃也算收尾,处理相同**)

> 术语澄清:**"使用中"= 还在做实验;"收尾但不归档"= 提交中/等待回复**。
> 两者**处理相同**(都属档①):只清垃圾,**不释放运行载体与原件**。区别只在研究是否还在推进,不影响清理。

| 档 | 触发(用户一句话) | 保留 | 释放 |
|---|---|---|---|
| **① 使用中 / 收尾未归档(=提交中)** | 立项后默认;"**收尾**了" / "**提交了**" / "等厂商回复" | ①知识(全局;**即查即用** —— 只写"来源: `<目标名>` `<日期>`",**禁写任何目标内文件路径**(含 `<目标>/artifacts/…`、`state/…`))②**对外材料**(`report/`:advisory/INDEX/attack-surface/CLOSURE/复现包)③重下凭据(`intel/firmware/*/SOURCE_URL.txt`:URL+size+MD5)**④运行载体**⑤队列/下一步需要的派生物(如 app 层要用的 `pat_out/`)**⑥内部证据**(`artifacts/`:agent 自查用 —— **队列/下一步要用到的就留**) | **只清垃圾**(`/tmp`、会话日志、运行残留)+ **`artifacts/` 里队列用不到的**(内部证据不属"永久保留",见下 ✓)。**"收尾"≠"释放运行载体"**:载体要留到归档 —— 结论复核、PoC 复跑都要它 |
| **② 归档 / 不要了** | "**这个目标归档了**" / "**不要了**" | ①②③(放弃时另留**一行记录**) | **④运行载体 ⑤派生物 ⑥内部证据(`artifacts/`)⑦原件文件**;其中 ⑦ 需满足"可重下"三条件:③在 / 链接可再取 / 不在提交中 —— 否则保留 |

- **为什么以前说 `artifacts/` 不删(现已修正)**: 旧条文把 ② 写成「`report/` + **被报告引用的 `artifacts/`**」⇒ 看起来 artifacts 属"结论证据"永久保留 ✗;
  但对外材料的红线是"**禁止引用内部证据**"⇒ 那个限定词**永远为假** ⇒ 成了死条文 ✗。
  现在: **②只含 `report/`**;**`artifacts/` = 内部证据(agent 自查用)** —— 档①按需保留(队列/下一步要用的 ✓),其余可释放;档②整体释放 ✓
  (**永久保留的只有**:①知识 / ②对外材料 / ③重下凭据 —— 三者与 `artifacts/` 无关 ✓)。
- **容器模拟的清理(硬)**: 模拟完必须清 —— 容器 `docker rm -f <自己名字>`,镜像 `docker rmi <自己构建的>`;容器/镜像一律用**唯一名字前缀**(如 `fw-<目标>-`);
  **禁** `docker system prune -a` / `docker volume prune` / `docker rmi $(docker images -q)` ✗ —— 本机还有**别的项目**的镜像。
- **容器挂载隔离(硬)**: 优先容器内工作目录或 named volume;必须 bind 时只挂**本目标的目录**(`state/<目标>/…`),需要写宿主就 `:ro` 或复制进出;
  **禁**挂 `/`、`/home`、`/etc`、`/mnt/c`、`/mnt/d`、整个 `/tmp` ✗;**构建/运行脚本里禁止对宿主路径 `rm -rf`** ✗。
- **容器化复现包**: 若复现依赖容器,包内必须带 **`Dockerfile`(或 `docker-compose.yml`)+ 一行 build/run 命令**,README 写明"用完删容器与镜像"。

- **自建工具**不属上面那 6 类 —— 它们是**机器能力**,不随任何目标收尾:工具本体装 `~/.local/bin/`(或 `/usr/local/bin/`),
  与 `afl-qemu-trace`/`libqasan.so` 同级登记在 `AGENTS.md`「环境清单」;**使用/判读用的小件(探针、脚本)**放 `tools/`。
  恢复路径**按各工具实际情况写,不许想象**:有源码/配方的(如 `afl-*` 的源码在 `~/opt/AFLplusplus-stable/`)就地记明;
  **没有的就明写「不保留构建法」**(如 `qemu-aarch64-patched` —— 只有机制记在 `knowledge/tool-quirks.md`,别去找/别去重建)。
  ⇒ `state/<目标>/` 里出现工具的大体积副本属**放错位置**:随时可删,权威永远是**机器上那份**(不是副本)。
- **双源清理(硬)**: 同一份东西**只存一处**。canonical 三处固定 —— ①**工具本体**在机器上(`~/.local/bin`/`/usr/local/bin`)、
  ②**判读/用法材料**在 `tools/`、③**目标内只留目标专属件**(该目标的跑法脚本、证据、报告)。
  目标里出现"与 canonical 内容重复的探针/README/大二进制" ⇒ **删那份**,并把 `notes.md` 等引用**改指 canonical**(留一行痕)。
  判据 = 两份同源、其中一份不在 canonical ⇒ 删副本(不是"两份都留,以后再说")。
- **④/⑤ 的判据(硬;可机械核)**: **删掉它,`report/attachments/*/poc.sh` 就跑不起来 ⇒ 它是④运行载体**;
  删掉仍跑得起来 ⇒ 它是⑤派生物(留着是为了"下一步/队列输入"或"重建省事")。
  ⇒ 载体/派生物**不看目录名**,看 **PoC 依赖**(例子:仿真 chroot 根 `emu_root`=④;`.pat` 解包物 `pat_out`、SPK 解包物、原文件系统 `rootfs`=⑤)。
  `tools/derived_check.sh` 会按此判据机械检查(poc.sh 引用到的路径必须存在)。
- **释放的授权来源(硬)**: 释放 ④运行载体/⑤派生物/⑥原件,只有**用户明确说了「归档 / 不要了 / 腾空间」之后**才能做;
  **禁止代用户宣布** —— notes/KB 里不得出现"用户宣布本目标已收尾"这类话,除非**引得出用户原句**(或该轮用户消息原文);
  拿不准 ⇒ **保留**(误留 = 占空间;误删 = 证据/复现链断)。出处:2026-09-26 我(开发会话)批量删了 5 个目标的 `rootfs`,
  还替用户写了"用户宣布已收尾" —— 属误删 + 假冒裁决。
**释放前 3 检**:①跨目标引用 ②**对外文件(advisory / `VR-*` / CVE 材料)无内部路径引用**(既有红线 ✓)**—— 注意 `INDEX`/`attack-surface`/`CLOSURE`/`notes.md` 是"内部归档",反过来**要求**带证据引用(路径/命令/输出 ✓),别把它们一起禁掉 ✗ ③配方齐 —— 任一不满足 ⇒ **不删**。
- **`artifacts/` = 内部证据**(agent 自查用;**KB 条目也不得依赖它** —— KB 要"即查即用")⇒ **档①按需留 / 档②整体释放** ✓;
  `notes` 里的引用**可断链**(注明「已释放 / 重建配方见 …」)✓;**大体积派生物统一放 `artifacts/work/` ⇒ 释放 = 删一个目录** ✓。
- **归档时才动运行载体(硬)**:运行载体在档①**一律保留**;只有到档②(归档/不要了)释放它时,才要求
  `report/attachments/*/poc.sh` **不依赖被释放的东西** —— 二选一:①**保留**该载体(CLOSURE 注明"为 PoC 保留,非归档件");
  ②在各 README 写"**从原件重建的配方**"。判据:载体档②释放后,`poc.sh` 仍能按 README 跑通;否则不算自含。
**释放后**:`bash tools/derived_check.sh <目标>` PASS(含「引用完整性」)⇒ notes 记一行(**删了什么 / 保留什么 / 怎么重建**)。
**重开**:用 ③ 重下原件 → 按配方重建 ④⑤(重开不需要重建"状态"概念 ✓)。

### "打不了"的常见形态与可选做法(原则在 AGENTS 守则 8/10/11;这里只列**做法**,不是规则)
- **没有真机/硬件**(本工作区常态) → 不是"没做": **容器/仿真/提取镜像的验证即为准绳**(判据与"注明遗漏"的写法见 `AGENTS.md`「停 / 不停」);不得据此停工或降级。
- 没凭据/没已认证视角 → **建场**(DB 写主体·自签证书·置配置态·读运行时材料·直连信任边界);
- 没对照 → 用同一目标的 **pristine vs 预设**、或同族实现/版本差分、或"同请求换主体"自造对照;
- 被否证 → 换**入口 / 主体 / 配置 / 前提**再试一次同一条后果链,并把这条链写进 notes;
- 判"面已穷尽" → 至少能给出一种覆盖证据: 输入枚举表、参数矩阵、或覆盖率数字。

### 停止声明(格式与证据,硬)
**格式(唯一规范;每次真正停下时用 `state_add_log(kind=stop)` 写 DB,notes 可留摘要)**:
```text
本轮停止: 判据满足 | 外部限制(<上下文余量(须引 harness 原句) | 工具/环境不可用(附证据原文) | 需用户输入>)
未满足的 Exit Criteria: <哪条没满足>
下一步第一条: <恢复时第一件事> | 理由=<排序因子> | 先试技术=<oracle × 导航>
```
- 三行停止声明里,"本轮停止"的理由**必须附证据**:判据满足 ⇒ 引 `derived_check --closure` 输出;
  需用户输入 ⇒ 写出"要什么/挡住哪一步/为何不能自造";工具/环境故障 ⇒ 附错误原文或现象(uptime 归零等);
  「上下文余量」⇒ **引 harness 的原句**(它在 20% 时不会给你任何提示)。**拿不出证据 ⇒ 不许写停止,继续做**。

### 需求式记录(硬):"缺什么"必须写在明面上
凡"没做 / 做不了"的,一律写成**需求式一行**:
`要做 <X> ⟹ 缺 <Y>;能否自造: 能(怎么造) / 不能(需用户提供 <Z>)`。
**禁止**只写成"未有 X""仍需 Y""记为待办"这类**否定式/叙述式** —— 那等于把缺项**埋掉**:
下一个 session(以及用户)会找不到"到底缺什么",于是无法在本地把条件造出来。
停止声明里的「未满足的 Exit Criteria」与「下一步第一条」尤其适用(实例: 2026-09-21 第 13 轮把
"需两个主体才能测水平越权"从剩余项里删掉,只在 §26.4 中间留了一句"仍需两个真实会话")。

### "理解该面"(建模)的产出模板(状态机第 5 步)
每个面在"构造利用形态"之前,写 3–5 行:
```text
信任边界: <谁不被信任 / 判定发生在哪一层(nginx? 中间件? handler?)>
输入可控点: <攻击者能控制哪些值;从哪进来>
决定安全的判定点: <函数/文件行/条件式 —— 或"产品无此概念"的代码依据>
已知保护: <限流/特性开关/mTLS/掩码/单次令牌…>
推翻它需要什么: <一句话:要怎样的输入/状态才能越过去>
```
用途: 它是**预测漏洞位置**的依据,也是**负结论的依据层级**(只到 L1 就写"未见",不许写"设计内")。

### 跨版本迁移的 finding:旧结论只作"思路与原料"(硬)
旧版本(或前目标)产出的 finding/advisory,**在新版本上未经复验前不算提交材料** —— 它只能提供:思路、工具、配方、路径;
**要在新版本提交,必须在最新 stable 上原样复验一次**(并作为**一条 H 条目**排进新目标的队列;复验结论按新版本的证据写)。
理由: 版本差分可能已修(那就降级为信息项),也可能形态变了(那就重写判据);"旧版本有、新版本没跑"= 未验证,不是 finding。

### 上游 vs 自研:怎么判、怎么排(硬判据)
**判"厂商自研/改写"的证据(任一即可)**: 厂商命名空间/前缀的二进制与符号(`syno*`/`ubnt*`/`mikrotik`/自研守护名)、
被改过的上游配置文件、厂商插件目录、version 串/构建路径与上游发布不一致、stripped 但仍保留自研 handler 名。
**处置三步**: ①**上游本体** ⇒ 只做**版本-CVE 排除**(结论进排除清单,**永不成发现**);②**厂商接线/胶水/权限映射** ⇒ 正常审
(这是自研缺陷主产区);③**上游本体深挖**(源码级 / 协议级 fuzz)⇒ 仅在拿到源码或能自建 fuzz 环境时做,否则写成假设池条目并注明依赖(高成本备选)。
**理由**: 上游 bug 不是厂商能改的、且要源码与 fuzz 预算;厂商自研代码才是它必须自己负责、也只有它这里才有独特缺陷。

### 文件搜索 / 扫描边界(守则 12b 的细则)
- **禁**: 以 `/` 或 `/mnt/*` 为根的递归遍历(`find /`、`grep -R /`、`rg /`、`du /`、`tree /`)✗(harness 层 `scan-guard` 会拦);
- **优先搜索根**: `$PWD`、`state/<目标>/`、`~/src`、`~/opt`、`/usr/bin`、`/usr/lib`、`/usr/local`、`/opt`、`/etc`;
- **工具发现阶梯(便宜→贵,命中即停)**: `command -v <tool>` → `dpkg -L <pkg> 2>/dev/null` → `ls /usr/bin/<tool>* /usr/local/bin/<tool>*` → `find <已知目录> -maxdepth 4 -iname '<pat>'`;
- 必须从根搜: **先问用户** + `find / -xdev ... -prune` + 排除 `/mnt /proc /sys /dev /run`;WSL 上跨 `/mnt/c`、`/mnt/d` 的递归 stat 极慢 ⇒ **不碰**。

### 机械化 oracle 的选择(每个面必答;守则 11 的落点)
**不是"四选一",而是"静态打底 + 机械化叠加"**:
- **静态(必做)**: 读懂入口/判定点/数据流 —— 它给的是"**去哪儿找**",不构成"面已判"的依据;
- **机械化(格由这一面的输入结构决定,可多格)**: 该面**解析外来数据**(参数/JSON/XML/二进制/协议)⇒ 默认格 = `fuzz`/有界畸形输入矩阵;无解析器(纯配置/授权位)⇒ 差分;"**等价 oracle**"(直接跑目标自带的工具/解析器)**只在真能覆盖该面输入空间时才算一格** ✗;`符号执行`/`插桩` 按需叠加 —— 主判据由其中一格负责,其余交叉验证;
- **对照/差分是"技术",不是 oracle 选项**:它能证伪、能定位修复点,但**单独不改变 disposition**(见 `knowledge/methodology.md`「差分的正确定位」),别拿"我做了差分"当"这个面已判" ✓;
- 写作要求: **静态做了什么 + 叠加了哪几格 + 主判据是谁 + 为什么这个组合够**。
- **凡"能喂输入 + 能观测崩溃/行为"的面 ⇒ 至少跑一次最小 fuzz smoke** 才可判 No finding(证据 = 该夹具的**最小运行输出**,或等价的"等价 oracle"如**直接跑固件自带工具**);
  **"最小"就是下面这个量级(照着做,不要自己加码)**: ①**1 份合法种子 + 一次有界变异矩阵**(或**固定时长 ≤15 分钟**);②固定上限(**≤2 GB / ≤15 min**,记录峰值);③至少观测 **退出码 / 耗时 / 输出长度 / 是否崩溃** 中的两项;
  ④**跑完无异常 ⇒ 就是该面的 No finding 证据**(⑧ 写清:种子=… / 变异=… / 时长=… / 结果=无异常)—— **别把"没找到"当"没做"** ✗。
- 选**静态**时必须写明"为什么静态足够"(纯配置 / 无解析器 / 无输入点 / 输入不可控);
  **"无解析器"的判据 = 点不出解析函数名** ⇒ 能指到 `parse*/decode*/strtok/sscanf/json|xml` 类函数就先当解析器面处理 ✓;说"观测不了"必须**同时给替代判据**(无输入点 / 只能真机 ⇒ 降级理由)✓。
- **选格要论证(硬)**: 选哪格**由面的属性决定**(有没有输入点 / 解析链是否自含 / 判据是否依赖设备现场状态 / 观测手段 / 单次执行成本),
  **不能按"哪格省事"选**;必须写下 ①**选它的依据** ②**为什么不选别的格**(具体到卡在哪、代价从哪来,可被反驳)。
  以下常见权衡**仅供参考,不代替判断**:
  - 面**小而自含**(解析链不依赖厂商私有库 / 不依赖设备现场)时,符号执行(angr)的性价比常最好;打不动就写清**卡在什么**;
  - 判据**依赖设备现场状态**(`/etc/config/*`、SysV shm/sem、daemon 交叉)时,**等价 oracle**(跑同一份厂商代码)常更划算 ——
    但要给出"符号执行在此的代价来自依赖"的**具体理由**,而不是"太贵"这种结论;
  - 能喂输入 + 能观测崩溃/行为 ⇒ fuzz(可先 smoke)常最直接,覆盖率证据(`afl-showmap`)是常见最低门槛;
  - 无输入点 / 纯配置 ⇒ 静态,并写明"为什么静态足够"。
- **跳过任何一格都要留痕**: 没用到的格,要么写明"为什么不适合本面",要么**作为候选写进假设池**(例:「该纯函数候选取样:上符号执行」)——
  **不许含糊掉** ✗。
- **判 No finding 前的三行(硬)**: ①本面用的格 ②该格的**最小证据**(等价 oracle 的输出 / `afl-showmap` 的 tuples / fuzz 的崩溃面)
  ③**为什么这个组合够**(含"没用其它格"的原因)。**缺任一行 ⇒ 不许判 No finding**。

- **"读码"不得作为唯一手段**(守则 11);工具找不到就走上面的**发现阶梯**,别 `find /`;
- 本工作区现状: AFL++ 5.02c 已装 —— **`afl-fuzz` / `afl-showmap` 在 `/usr/bin/`**;**`afl-qemu-trace`(自建,用于 qemu 模式)在 `/usr/local/bin/`**;源码 `~/opt/AFLplusplus-stable/`;angr/capstone 在 `~/ENTER/envs/pwn/bin/python`。

### 假设池 = **唯一队列**(活体;每轮更新)
**它是什么**: 全工作区**唯一**的"待打清单"。每条 = 一个可验证假设:`**H<编号>** <一句话机制>` + **偏差陈述**(为什么可疑:
观察到什么与预期不符)+ **可证伪判据**(跑什么、看什么 ⇒ 成立/排除)+ **位置/怎么验** + **状态**(未处理/进行中/定论/降级+理由)。
**谁往里写(单一漏斗,全部)**: ①A1 枚举出的 `未判定` 面;②机制镜/作者镜/状态镜的新面与新假设;③误判回溯命中集重验后的新方向;
④新观察升成的假设(须写满偏差陈述+判据才入池);⑤用户/情报给出的新线索。
**谁不能另立清单**: 不许再造 Lead / 重开 / 起点 / 待办 之类的平行清单 —— 历史事故:三个平行清单(`重开清单`/`Lead`/`起点清单`)
把队列架空,导致"最后还有没打的、也不按队列"。
**池的下限(四来源;机械可核)**: 池不只装「面」—— 每轮按四来源补齐,别让池停在面层:
①**面层**: A1 枚举出的 `未判定` 面;②**端点层(最常缺 ⇒ 池变小的真原因)**: 每个面要按建模第 ⑦ 行给出**端点/子面清单**,
   清单里**未判定的端点逐条入池**(给不出清单 ⇒ 写「未枚举」并**入池**,不许静默跳过);③**复发层**: 三镜与「新观察」(机制 / 状态·主体·版本复发);
④**纵深层**: 某个面的 handler **还没追到 sink**(参数第一次被使用的地方,见建模第 ⑦b)⇒ **必须成一条 `H` 入池** ✓ —— 这样"队列清空"才等价于"每个面都追到 sink 了" ✓(只写到"入口有鉴权门" ✗ = 未追完 ✓)。
**池太小的诊断(硬)**: `池条目数 ≈ 面的条目数` ⇒ 说明停在**面层** ✗(正常应因端点层而显著多于面数);补法 = 先导出该面的端点清单再逐条入池。
**同步不变量**: 池里已判的面 ⇒ A2 同行必须**同 disposition**(禁止「池已判 / A2 仍未判定」或反之)—— 出处:2026-10-03 TS-464 轮(`report/attack-surface.md` 与池状态一度打架)。

**降级准入(硬,判据驱动)**: 把 `H` 条目降级/收尾的必要条件 = 该面的**可证伪判据已被执行并给出结果**(成立 → 变 finding;证伪 → 降级),或**明确不可执行**(需工作区外的东西,并写明为何不能自造)。
**"轮"的声明格式(硬,机械可核)**: 每轮**开头一行** `本轮目标: H-xx`;**收尾两行** —— `本轮: H-xx → <定论/降级> + 证据`(同一 H)+ `新观察: <本轮看到的、与预期不符的事实 | 无(判据: …)>`;
**"新观察"是假设的生成侧(硬)**: 它就是双输出(判定 + 观察)里的后半 —— 新观察 ≠ 无 ⇒ **同轮内升成 `H-xx` 入池**(带偏差陈述 + 可证伪判据);它喂的仍是**同一个假设池**,别另立清单 ✗;写"无"必须带判据;
**无目标的收口 = 违规** ✗: 出现 `本轮:` 收口却没有对应的 `本轮目标:`(或同一 H 的收口重复)= 把工作偷偷塞进别的轮 ⇒ 闸门记"轮结构违规"(出处:2026-10-03 UDM 轮实测 —— 2 个 `本轮目标` 对 5 个 `本轮:`,其中 H-09 的降级行重复两次);
**半轮不是停** ✗ —— 声明了目标却没把它推到"oracle 结果或判定性结论"就收手 = **半轮**,护栏会抓(`ROUND=half` ⇒ 提醒继续)。
**一条 H 一轮(硬)**: 一轮只声明 **一个** `本轮目标: H-xx` ✗ 不要把后续工作塞进同一轮 —— 一轮内出现 ≥2 个 `本轮目标:` ⇒ 闸门记"轮结构违规"。
**finding 即收口**: 若某轮产出了**本轮新成立 finding**,该 finding 就是**本轮的收口**(写判定 + 证据 + 材料状态 / 或用户已裁决"不打包")⇒ **本轮结束、汇报**(这是四种合法停之一);
后续工作**另起一轮** ✗(不要在同一轮里继续扫别的面 —— 那会让 finding 的材料没人管、用户也无法介入)。
出处:2026-09-29 QNAP 轮实测 —— 它把"一轮"理解成"从我说继续到它停" ✗,于是拿"本轮做完了"当偷懒接口(实际把一个 H 拆成十几轮、中途反复交回)。
**"轮"不允许由 agent 自行切分来凑数** ✗ —— 一次"轮" = 把一条假设推进到 **oracle 结果或判定性结论**;判据没跑完就写"本轮结束/边界/维持现状" = **违规**(成本、时间、工作量都不是理由)。
**"自造但重 / 成本高 / 要建复杂前置 / 时间不够 / 已跑了几轮"都不是降级理由** ✗ ⇒ 条目**保持未处理**,继续做(能造就必须造;判据没跑完就得跑完)。用降级把条目摘出队列换取收尾 = 违规。

**状态一致性(硬)**: 一条 `H` 条目**二选一** —— ①**队列项**(状态=未处理/进行中)⇒ 它才会出现在"下一步第一条";
②**已定论/降级**(状态带结论或降级理由)⇒ **不得再写成"下一步第一条"** ✗。若还想做 ⇒ 它就不是降级,应**改回"未处理"重新入队**(或写成"可选、需用户裁决"并明说)。
换句话说:**"下一步第一条"与假设池状态必须一致**;`derived_check --closure` 会拦这种矛盾。

**取项(自动继续)**: 每轮从池中**未处理**项按排序因子取队首;**判完一项若结论是 No finding/排除/降级且没有外部资源缺口 ⇒ 立刻取下一项**,不返回用户
(停的条件只有四种:**本轮新成立** finding / 需要工作区外的东西 / 队列清空 / 目标级裁决 —— 见 AGENTS「停 / 不停」;
**历史 finding 不构成停止理由**,队列还有未处理项 ⇒ 继续)(常规态优先 → 预认证 → 报文级 → 未理解度 → 复杂度);改选别项须写下"为什么改选 + 队首项怎么处置"。
**closure 不变量(机械可核)**: `{A2 的 disposition=未判定 行} ⊆ {池中未处理/进行中条目}`;池中有未处理条目 ⇒ 收尾只能
"逐条给结论或显式降级",否则不许收尾。

### 误判回溯(证据驱动;**不要做无脑对账**)
**触发**: 任何时候发现一条**已判定**结论是因**过程**错误而错(不是分析错)。
**动作(四步,不许只修那一条)**:
1. 写下**错误类 + 受影响谓词**(可判定的描述),例: "结论句含『无监听/面不存在』且证据里没有就绪判据"、
   "地址取自 <已知有 bug 的工具>"、"样本取自 <错误状态/错误站点>"、"缺对照";
2. 按该谓词**扫全部历史结论**(notes + report 全量),列出**命中集**;
3. 命中集逐条**重验**,或明确标"未复核";
4. **把该谓词记进 notes** —— 同类错误下次直接复用(谓词是资产);
   命中集重验后若产生**新方向/新假设** ⇒ **写入假设池**(不另立清单)。
**为什么**: 误判极少是孤例(同一个过程会污染**一批**结论)⇒ 按**谓词**回溯,比"什么都不知道地全场重扫"更准、更省。
**首个实例(2026-09-21)**: 清点发生在就绪前 ⇒ 谓词 = "『无监听/面不存在』且无就绪证据" ⇒ 命中 6 行
(row 2/4/6b/10/11/1g);现场复核已证伪 row 11(`10003/3478/5514/6789/8080/8843/8880/28082` 在 `running` 后均在监听)。

### 三镜刷新(**一个面/格收口时 1 行**;再入 A1 的回边 | 同时是收尾前置之一)
**触发点(硬)**: 一个**面被推到 disposition**(No finding / Vulnerable / Out of scope / 显式降级)时,或**一个技法格跑完**时,
贴一行(3 行以内,格式固定);**下限:至少每 3 轮一次**(防攒批 ✗)。
```
三镜: 机制=<该机制在同族/别的面会怎么复发 ⇒ 结论> | 作者=<若我是作者,最可能漏检的那一处 ⇒ 结论> | 状态=<换状态/配置/主体/版本还成立吗 ⇒ 结论> | 新面=<无(判据: …) | H-xx(已入池)>
```
- **运行态对账(并进状态镜;通用做法 —— 工具由目标自选,别写死)**: 每次三镜**顺手回答一句**「**我手里的面清单,是不是站在*运行/就绪态实测*上?**」
  拿得到 ⇒ 抓一份**当轮快照**(端口/连接/单元/进程/路由…**目标自带什么就用什么**,系统里现成的手段即可 ✓)并与 A1/A2 **逐条对账** ——
  **就绪态多出来的每一条都要有 disposition**(新面 ⇒ 入池 ✓);拿不到 ⇒ 写明「未取得 + 静态替代判据」✓。
  **只靠静态枚举的 A1 不算完整** ✗(依据:`LOOP`「扫面 / 提取」的「清点前提(硬)」「对账(硬)」,本条只是把它们挂到每轮刷新上)。
- `新面=无` **必须带判据**(写不出的不算结论);`新面=H-xx` ⇒ **同一轮内必须已写入假设池**(这一条治的是"队列冻结" ✗)。
- 出处(硬):2026-09-29 QNAP 轮实测 —— **45 轮里只做过 1 次**(§7 之后再无)⇒ 新面从未入池、池冻结在 15 条 ⇒ 收尾时"队列清空"成空话 ✗。
- 闸门:`tools/derived_check.sh` 检查**最近 3 轮**(至少要有一行);日常跑**提示**、`--closure` **FAIL**(最近 3 轮无该行,或新面未入池);已收尾目标豁免 ✓。
- 局限:闸门只看**最近 3 轮**(没法逐轮回溯)⇒ 它保证"最近做过 + 新面入池",管不了更早的历史轮 ✓。
它不是"再枚举一遍",而是**给循环加一条回边**:第 8 步之后带本轮学到的东西回到第 3 步。
**前提(硬)**: 清点在**面枚举(A1)**那一步就必须在**就绪态**做(判据由目标自带 + 留证,见「扫面 / 提取」);
枚举完整性以"**就绪态实测清单**"为输入 —— **不靠事后无脑对账**(见下「误判回溯」)。

**三镜(每镜都要给结论,不许空过)**:
- **机制镜**: 已证机制在别处怎么复发?(别的 server 块 / include 组合 / 其他 runnable / 其他型号·状态);
  - 还要问:**同一入口下尚未审的端点面积**(例:`/proxy/network/*` 背后的 controller REST API)。
- **作者镜**: 若我是作者,这个功能/配置**最可能在哪里漏检查**?(从设计意图找薄弱点;与建模第 ⑥ 行是"全局 vs 单面"的关系);
**⑦该入口背后的端点清单**: 该面下的 API/端点(尤其**认证后的应用内面积**)要么给出清单,要么**显式写"未枚举"并进假设池**(不许静默跳过)。
**⑦b 纵深(三条轴里最常缺的一条)**: 判该面 No finding 前,必须给出**"入口 → 参数 → sink"**这条链 ——
  指到**参数第一次被使用的位置**(读文件 / 拼命令或 SQL / 写内存 / 当路径 / 进解析器 ✓),并说明**那一处有没有校验** ✓。
  **只写到"handler 入口有鉴权门"不算判完** ✗;只写"追到分派表"不算判完 ✗(分派表只是路由,不是 sink)。
  三条轴别混:**探索**=面/端点清单(第 ⑦ 行)、**刷新**=三镜、**纵深**=本条 —— 一条也不许拿另一条代替 ✓。
**⑧机械化 oracle(可叠加)**: **先问"这一面解析什么输入(语法/长度/结构)?"** 没有解析器就写"纯配置/授权位" ⇒ **由它选格**: 解析外来数据 ⇒ 变异/畸形输入(`fuzz` 或有界输入矩阵);无解析器 ⇒ 差分/静态;密码学门 ⇒ 静态即可;然后 **静态打底**(给理解与定位)+ **主判据由谁负责** + 一句理由;**只用静态时必须写明"为什么静态足够"**(无可喂输入的观测点 / 纯配置 / 无解析器)。组合优先:静态定位 → 动态确认 → fuzz 扫边界。
- **状态镜**: 同一入口/机制换个**状态(setup↔post-setup)·站点(server 块)·配置/特性开关·主体·版本**还成立吗?
**产出(都要留证;与「误判回溯」**解耦**)**:
- **误判回溯**: **必做,不需问用户**(错判必须回溯,见上一节) —— 证据触发,与刷新互不替代;
- **三镜**: 先把新面/新假设**找齐**,**逐条写入假设池**(带 偏差陈述 + 可证伪判据 + 位置/怎么验 + 排序),
  **然后直接取队首继续**(默认自动继续;仅"需要外部资源"或"目标级裁决"时才停 —— 见 AGENTS「停 / 不停」);**surface map 只加"面 × 属性"登记,不承载待办**;
- **无新面**: 写清扫了哪些维度、凭什么判无 ⇒ 才允许收尾(第 9 步)。

### 结论的**依据层级**(原则:结论强度 ↔ 静态深度)
**适用范围 = 一切对外断言**,不只是"结论/disposition":报告 Root Cause / Impact 里每一句**事实性或推断性陈述**
(例:"该窗口在真实流程中存在"、"影响范围限于 X")都必须挂依据层级 —— **限定条件也算断言**。
每条结论都要标出依据落在哪一层:
- **L1 行为观察**:实测响应/状态码/差分 —— 只支撑"**未证伪**"(即:我没打出问题),**不支撑**意图性结论;
- **L2 表·常量·配置**:DB 表/种子数据/权限位/路由注册点 —— 能支撑"该值恒为 X"这类事实;
- **L3 代码路径**:入口 handler → 关键判定点的引用(文件·函数·判定语句) —— **意图性结论**("设计内 / 不存在某边界 /
  该功能没有")**至少要到 L3**,否则只能写"未见/未证伪"。
**顺序不限**(静态先行、fuzz/符号执行先行都行)—— 要求的是**深度与结论匹配**,不是流程顺序。
- 正例(2026-09-21 §28.1 `_t`): L2(`role_system_key_idx` UNIQUE 索引、厂商默认播种命令)+ L2(mask 计算 8030)
  + L1(30 条路由矩阵)⇒ 才敢下"设计内";
- 反例(同日 §28.2 IDOR): 只有 L1(角色模型 + 8 条 GET 矩阵)就下"无水平主体边界" —— **依据层级不足**,
  且**只枚举 GET**,写方法(POST/PUT/DELETE 的 `:id`)与 body/`mac`/`name` 引用的对象未列。

### 反水坑(注意力分配,每轮迭代)
对照 surface map,注意力优先流向 **未覆盖 / 未理解 / 此前失败**的面;**否证 ≠ 面已穷尽**(只说明该假设不成立)——
记录已试方法与失败原因,换方法 / 换入口 / 换数据流再试;同一面**连续零产出**才允许降优先级;不允许单一线索长期占满注意力。
- **常规态优先**: 选面/收面时先问一句"这个面在**常规(已配置/在用)状态**下能不能打完整链?"。
  能 ⇒ 优先投入;不能 ⇒ ①把"**把窗口接到常规态**"(如:未认证的状态改变入口、可控的复位/迁移路径)写成 Lead 再选面,
  ②或明确记为"窗口级缺陷"并**减少**后续投入(不雕花)。窗口时长/影响范围进排序,**不进结论强度**(证据强度照旧分级)。
- **认证后并入倾向**: 立项时查过厂商口径(AGENTS 守则 10「厂商口径门」)且厂商接受认证后 ⇒ 认证后面**可进主线序列**,
  位置在"常规态预认证"之后、窄窗口缺陷之前。厂商无明确先例时按"未确认"处理(不因此排除,也不优先)。

### 扫面 / 提取(原"专项任务分派"内联步骤 A·C)
- **面 = 三态(硬)**: 入口**不止"监听 socket"** —— 至少三态:
  ①监听 socket(TCP/UDP/unix);②**收报文但非 listen socket**(NFQUEUE/netfilter 队列、`AF_PACKET`/raw socket、抓包守护);
  ③**非网络触发**(本地 unix socket 由 webapi/hook 驱动、cron/updater 定时、DB/日志/配置解析)。
  ⚠️ 只按 "listen" 清点会漏 ②③(例:2026-09-27 SRM 的 `resolvsrmd` 从 **NFQUEUE** 收 DNS 报文、SafeAccess `synosafeaccessfilterd` 做**报文过滤** —— 都不是 listen socket)。
- **扫面**: ①攻击面枚举(init 脚本/配置 → 常驻守护与**三态入口**;含**代理型入口**)②危险汇定位(入口→危险 API:
  命令执行/内存破坏/路径/解析器/鉴权)③数据流推理(入口参数→中间变量→全局/持久存储→sink;注意跨接口污染与认证覆盖缺口)
  ④证据固化(`文件:函数(地址)` + 反编译/反汇编片段)。**前置**: 先把反编译导出为纯文本再扫,不要对活体二进制盲扫。
  **清单须标注 自研/上游 + 版本**(供 §0 分诊:自研优先;上游只做版本-CVE 排除),落点是 surface map(`state/<目标>/notes.md §2.3`)。
- **分层全量导出(硬)**: 入口清点**不是"看到就记"** —— 至少导三层:
  ①监听 socket;②**路由表载体 / 反向代理 location**(nginx `site-*.conf`、apache `sites-enabled`/`httpd.conf-*`、自研 httpd、
  **运行时脚本生成的 conf**、框架路由注册表);③**封装应用包**(见下"提取")。artifact 写明**覆盖的层 + 取清单时的状态判据**;
  某些入口只在"功能面已激活"后才生成(按需安装/配置)⇒ 必须在**该面存在的状态**下再导一次(否则会像"就绪前清点"一样漏)。
- **清点前提(硬)**: 凡"监听端口 / 常驻进程 / 服务存活"这类**实测清单**,都必须在**就绪态**取,并把
  **就绪判据 + 取值**与清单一起留档(判据由目标自带: systemd → `is-system-running`;busybox/自研 init →
  健康端点、就绪日志行、监听出现且计数稳定;取不到就写明"未取得就绪证据",不得当成"不存在")。
  **对账(硬)**: **静态清单 ⊖ 就绪清单 = 待查漏项** —— 就绪态少出来的每一条都要给出"未按需激活 / 未生成 / 就绪判据没覆盖"的解释。
- **提取**: 先 `binwalk -Me`;产出贫瘠(<3 文件)或非标格式 → `unblob -e <out> <fw>`;**两个产出目录都检查**;
  提取器缺失导致格式静默失败 → 按「环境清单」补装后重跑。
  **先列顶层归档目录再逐层解**(明文 tar 的 `.pat`/`.spk` 这类**非魔数归档** binwalk 可能视而不见)。
  **顶层里的封装应用包必须单独列并入面**(如 Synology `packages/*.spk`:**独立代码基** —— 自带 webapi/handler/守护/前端与**自己的监听端口**;
  用 `find rootfs -iname "*<AppName>*"` 可验证"不在 rootfs 里")—— **不许只扫 rootfs 就宣称 A1 完成**。
  加密/高熵/非标固件走「环境清单」的"熵分析 → 解密 → 再解"分支。
  汇总: ①文件系统类型与根目录结构 ②敏感物清单 ③网络可达守护进程清单 ④**封装应用包清单**。**只做提取与清单,不做漏洞假设。**
