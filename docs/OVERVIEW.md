# 项目概览(给外部评审)

> 自含:读者看不到仓库也能理解。分层与纠正见 `docs/ARCHITECTURE.md`。

## 1. 一句话

固件漏洞研究的**作业系统**:给一个固件目标,agent 走"逆向 ⇄ 假设 ⇄ 验证 → 判定 + 新观察 → 更新假设池"的循环;
产出 = 有 finding 出 advisory + 自含复现包(+ CVE 备料),无 finding 出覆盖度结论 + CLOSURE。

## 2. 三层职责(核心原则)

- **模型**选行动(研究什么、用什么方法、怎么解释结果);
- **运行时**保证执行可靠(工具真实状态、超时/取消、上下文、持久化、恢复、追踪);
- **领域层**保证事实可靠(假设/尝试/观察/证据/结论的合法流转,不变量由程序强制)。

> 框架限制的是**不可靠的执行与无依据的状态变化**,不限制模型发现漏洞、选方法和探索新方向的能力。

## 3. 现在真正有什么(已实现 + 有测试)

- `fwcore.db`:SQLite 权威状态(目标/攻击面/假设/尝试/观察/证据/结论/工具调用/运行/检查点/事件/历史文档)。
- `fwcore.domain`:唯一写入口 + 不变量。关键几条:
  环境失败/信号不足/取消 **不能**推出结论;`refuted` 必须挂证据;结论必须写适用范围;
  `inconclusive` 必须写"还缺什么才能判定";`UNKNOWN ≠ EMPTY`;收尾阻塞项程序可核;并发写明确失败。
- `fwcore.tools`:描述式注册(名称/说明/JSON Schema/风险级)+ 真实执行状态(ok/error/timeout/cancelled + exit code + 落盘 + sha256)。
- `fwcore.runtime`:模型↔工具循环、上下文重建(不读 notes 猜状态)、检查点、`resume()`。中断 ⇒ paused,**不改变假设结论**。
- `fwcore.migrate`:把历史 `notes.md` 原文**逐字节**入库,池条目搬成假设并标 `needs_review`(不推断历史完成)。
  实测:QNAP TS-464 的 notes → 28 条假设,原文 byte-identical。
- `fwcore.cli`:独立入口 `fw-core`(**不依赖 Pi**):init/hyp/surface/attempt/evidence/observe/conclude/status/derive/view/run/resume。
- 21 个测试(不变量 / 工具状态 / 中断恢复 / 迁移保真 / 并发锁)。

## 4. 明确没有做的(不要误读)

- **没跑过真实模型评测**:`OpenAIModel` 有实现,但所有运行时测试用脚本化模型 ⇒ 只能证明循环与恢复正确。
- 工具集只有 4 类;没有 IDA/Ghidra/fuzz/仿真的工具化。
- 闸门仍在 Markdown 上跑(未迁到权威状态)。
- 没有 CI;迁移只覆盖假设池。

## 5. 与外部项目的关系

同:PentestGPT / HackingBuddyGPT / XBOW 这类系统都把"研究与执行"分开、把组件做成可测的;
OpenAI Agents SDK 的"运行循环/工具/会话/护栏/追踪"、MCP 的"工具描述驱动发现"、LangGraph 的"检查点与恢复"
是我们直接借鉴的工程做法(但只借语义,不照搬结构)。
异:**不做自治渗透**;证据优先;**把研究纪律里可机械核的部分做成不变量**(这是最值得评审挑的地方)。

## 6. 想被挑战的地方

1. 取舍:哪些"研究纪律"应该进不变量,哪些必须留在人的判据里?(进多了会把研究变成流水线)
2. `inconclusive` 必须写"下一步判定条件"这条,会不会变成新的格式负担而没改变行为?
3. 权威状态是 SQLite 单库:未来多目标并行/多会话时,是否需要租约(lease)而不是靠写锁报错?
4. 迁移只保真原文:历史结论要不要逐条人工核对?核对成本怎么摊?
5. 没有真实模型评测前,怎么判断"研究自主性提升"不是文本幻觉?
