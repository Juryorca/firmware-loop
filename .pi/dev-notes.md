# 开发侧笔记(仅开发用 session;研究 session 不读,任何提示词/知识库文件都不指向本文件)

> 用途: 放**开发工作**(改提示词、重构结构、复核他轮)产生的东西 —— 这些东西研究 session 完全不需要知道,
> 所以**不写进** `AGENTS.md` / `LOOP.md` / `knowledge/` / `tools/templates/`。

## 1. 复核另一轮 / 另一 session 的产出(做法)
以**被复核者的产出为主体**,不要拿复核者自己的结论当检查表(那样只会确认偏差,并漏掉对方的新发现):
1. **忠实重建其过程**: 它选了什么面 / 用什么方法 / 跑了什么 / 得到哪些**观察(原子事实)** / 结论是什么(先不带自己的预判);
2. **先抽它自己的发现**: 新面 / 新机制 / 新事实(包括复核者上次没列到的),以及它的假设与**否证**;
3. **看它如何处理"难"**: 缺条件时是**造条件**还是停;造的条件是**产品自身状态**(型号 / 默认值 / 安装器写入)还是**手改出来的**
   (后者只能算对照 —— 见 `knowledge/methodology.md`「建场」边界二);
4. **然后才对照复核者的预判**: 我上轮列的坑它踩/绕各几个;它是否**指出复核者错了**(按证据接受,不辩护);
5. **分歧逐条裁定**: 给证据判,不默认复核者对;裁定结果转成下一轮工作项(写进目标 notes)。

## 3. 提示词工程的三条标准(开发侧沉淀)
1. **边界常驻,判据外放**: 影响"是否开工/停工/越界"的写进常驻提示词(短);"怎么判断"的经验放知识库,由**状态机节点上的
   "此处必查"**触发,而不是靠常驻规则提醒 —— 常驻规则堆在一起会自相矛盾(曾同时写出"预认证>认证后"与"需配置的面只能标 Out of scope");
2. **交付物形态一律在模板**: 提示词里出现"骨架/格式/字段清单"就是违规(曾把 168 行报告规范留在提示词里,而同一文件又写着"不要在提示词里重复模板内容");
3. **原则优先于特化规则**: 给方向(如"把'打不了'当成'我还没把条件造出来'"),不要写"遇到 A 就做 B"的触发式条款 ——
   模型能力够,缺的是方向感;特化条款过拟合、会互相打架。

## 4. 已用过的"懒结论"识别式(供复核时快速扫)
结论句里出现 **"需 X 才能…" / "未实测" / "若换目标再判" / "Blocked: 需凭据" / "No finding: 需 mTLS"** ⇒ 那不是判定,
是**待造条件**;要问"能不能在本地把它造出来"(建场)或"能不能用经验直接判"(语义上是否越权)。

## 5. 观察到的"带歪"现象(2026-09-21;供复核时快速识别)
1. **缺项埋进散文**:真正的缺项(如"需要两个真实主体/账户才能测水平越权")只写在**中间章节的一句叙述**里,
   而**停止声明的"未满足项"与"下一步"把它删掉/改写掉** ⇒ 用户与下一轮都找不到"到底缺什么"。
   (实例: 第 13 轮 §26.4 第 1009 行 vs §26.6 —— 剩余项被从"1c+垂直越权+双主体 IDOR"改写为"宿主侧+`_t`"。)
2. **否定式/叙述式代替需求式**:写成"未有 X""仍需 Y""记为待办",而不是"要做 X ⟹ 缺 Y;能否自造: 能/不能"。
3. **把可造条件说成外部依赖**:"仍需两个真实会话" —— 而身份/用户在本地方可造(DB 写入 / 内部头 / 自签证书)。
4. **无边界停止理由**:"预算(时间/步数)"(已改为"可指认的外部限制")。
5. **优先序错**:把"离定论最近"的线索留在身后去开新面(换面代替深挖)。
6. **收尾词汇误用**:`diminishing returns` / `coverage complete` 在前置条件不满足时被使用(需逐条核对前置)。

## 6. 待观察项:"用模型反推"(研究员动作,尚未显式化) | (2026-09-21)

"如果我是作者,我会在哪里漏掉检查?"(而不是从输入空间穷举)。

1. 是否自发出现**意图出发**的推理句("产品这样设计 ⇒ 这里最可能漏掉 X");
2. 该反推是否**落到判定点/候选位置**(函数/条件/路由),而不是停在"可能有问题";
3. 是否与建模第 ⑤ 行衔接(用模型预测位置 → 再构造形态)。
若连续 2 轮都不自发出现,再考虑把它写进建模步(届时只加一句: "⑤ 之外再写一行: **若我是作者,最可能漏检查的位置是 …**")。

## 10. 机制设计:三镜刷新(再入 A1)+ 误判回溯 | (2026-09-21,用户提议,两轮迭代)
**问题**: 我们原来的节奏是"假设 → 逐个验证",而**面枚举(A1)被当成一次性产物** ⇒ 只有"已经被枚举到的面"才会被假设覆盖,
**枚举本身漏掉的东西永远进不来**(实证: SNMP `0.0.0.0:161`、UDP 10003/3478/5514/6812/6813/7812/7813、
TCP 6789/8080/8443/8843/8880/28082/9443 在 A2 表里缺失或与运行态矛盾;而"无监听"结论**很可能是在 systemd 还
`starting` 时数的** —— 同一镜像 starting 阶段 5 个监听、running 后 40+ 个)。
**机制(优雅处 = 一条回边)**: 状态机第 8 步之后加 **8b 三镜刷新(再入 A1)**: 带本轮学到的三副镜片回第 3 步 ——
- **机制镜**(同机制复发面)/ **作者镜**(若我是作者最可能漏检查哪)/ **状态镜**(换状态·站点·配置·主体·版本);
产出二选一: **新面 → 继续循环** / **"无新面 + 判据" → 才可收尾**。
**前提(硬)**: 清点必须**就绪后**(`is-system-running=running`),且**运行态监听与 A2 表逐条对账**。
**它合并了**: 之前的「机制范围」+ 建模「作者视角」+「换维度一等动作」+「就绪清点」—— 四处分散的洞用一个回边收口。
**可核化**: `derived_check.sh --closure` 现在检查 ①A2 无 `未判定` 行 ②notes 有「三镜刷新」节且三镜都有结论
③`artifacts/recon/listening-reconcile.txt`(就绪后的 `ss -lntup` 原样输出)存在,且其中**每个端口都能在
`attack-surface.md` 里找到**(找不到 ⇒ FAIL)④论点—证据表节内"缺口"行已限定/降级。
实测当前目标 = **FAIL x3**(未判定行 / 无三镜节 / 缺对账文件);常规模式仍 PASS。
